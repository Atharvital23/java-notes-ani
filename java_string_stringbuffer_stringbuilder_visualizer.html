Java String vs StringBuffer vs StringBuilder

Architectural Comparison, Memory Models & Complete Method Explorer

String

java.lang.String

Immutable sequence of characters. Once created, its internal character array cannot be changed.

  • Thread-safe (due to immutability)
  • Uses String Constant Pool for memory optimization
  • Slow for frequent modifications & loops
String s = "Hello";
s = s + " World"; // Creates new object
StringBuffer

java.lang.StringBuffer

Mutable sequence of characters with thread-safe (synchronized) method execution.

  • Mutable in-place modifications
  • Thread-safe (methods are synchronized)
  • Slower due to synchronization overhead
StringBuffer sb = new StringBuffer("Hello");
sb.append(" World"); // Modifies in place
StringBuilder

java.lang.StringBuilder

Mutable sequence of characters, non-synchronized. Introduced in Java 5 for high performance.

  • Mutable in-place modifications
  • Fastest performance (no synchronization)
  • Not thread-safe (unsafe in multi-threaded code)
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // Modifies in place

Decision Guide: Which one to choose?

Use String when:

You are dealing with fixed text literals, configuration values, method parameters where immutability is preferred, or keys in HashMaps.

Use StringBuilder when:

You are doing extensive string manipulation, loops, or concatenation in a single-threaded environment (95% of use cases).

Use StringBuffer when:

You need mutable string operations shared concurrently across multiple threads (thread-safe builder).

Performance Pro Tips

  • Initial Capacity Sizing If you know the approximate final size, initialize `StringBuilder` with capacity: `new StringBuilder(256)`. This avoids costly internal array reallocation and copying.
  • Compiler Optimization (Java 5+) Java compiler automatically converts simple string concatenations like `"Hello " + name` into `StringBuilder` under the hood. However, inside loops, always explicitly use `StringBuilder`.
  • String Interning Use `s.intern()` to ensure identical strings share the exact same memory reference in the JVM String Pool, optimizing memory for high-repetition categorical data.
