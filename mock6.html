1. Components of JVM

Definition: The Java Virtual Machine (JVM) is an abstract machine that provides a runtime environment in which Java bytecode can be executed and run.

The 3 Most Important Components:

  • Class Loader Subsystem: Responsible for loading (`.class` files), linking (verifying and preparing memory), and initializing classes into the JVM memory.
  • Runtime Data Area (Memory Area): Divided into Heap (objects), Stack (methods/local variables), Method Area (class metadata), PC Registers, and Native Method Stacks.
  • Execution Engine: Executes the instructions contained in the bytecode. It contains:
    • Interpreter: Reads and executes bytecode line by line (slower).
    • JIT (Just-In-Time) Compiler: Compiles frequently used bytecode (hotspots) directly into native machine code for high performance.
    • Garbage Collector (GC): Automatically frees up heap memory by destroying unreferenced objects.

Real-World Analogy

Think of JVM as an automobile factory. The Class Loader is the parts delivery truck bringing raw components. The Runtime Data Area is the assembly floor where parts are sorted and stored. The Execution Engine (JIT/Interpreter) is the workforce and machinery building the final car, while the Garbage Collector is the cleaning crew clearing away scrap metal and debris.

2. What is a Class & How JVM Loads It

Definition: A Class is a blueprint or template from which objects are created. It defines state (fields) and behavior (methods).

Class Loading Mechanism: When you run a Java application, the ClassLoader loads the `.class` file through three main phases:

  1. Loading: Reads the `.class` binary file from the disk/network and generates a corresponding `Class` object in the Method Area.
  2. Linking:
    • Verification: Ensures bytecode is safe and valid.
    • Preparation: Allocates memory for static variables and assigns default initial values.
    • Resolution: Replaces symbolic references with direct memory references.
  3. Initialization: Executes static blocks and assigns actual values to static variables.

Code Example: Dynamic Class Loading

public class ClassLoadingDemo {
    public static void main(String[] args) throws Exception {
        // Dynamically load a class at runtime
        Class<?> clazz = Class.forName("java.util.ArrayList");
        System.out.println("Loaded Class: " + clazz.getName());
    }
}

3. Difference Between `float` and `double`

Definition: Both are primitive floating-point data types used to store fractional numbers conforming to the IEEE 754 standard.

Float (32-bit Single Precision)

  • Size: 4 Bytes ($32$ bits)
  • Precision: ~6 to 7 decimal digits
  • Suffix: Requires f or F (e.g., float f = 10.5f;)
  • Use Case: Large arrays of graphics/game coordinates where memory is constrained.

Double (64-bit Double Precision)

  • Size: 8 Bytes ($64$ bits)
  • Precision: ~15 decimal digits
  • Default: Default type for decimals in Java
  • Use Case: Scientific calculations, general decimal math, high precision needs.

Code Example: Precision Loss

float f = 123.456789f;
double d = 123.45678901234567;
System.out.println(f); // Output: 123.45679 (precision cut off)
System.out.println(d); // Output: 123.45678901234567 (full precision)

4. What is a Thread Pool?

Definition: A Thread Pool is a collection of pre-initialized, reusable worker threads waiting for tasks to be assigned. Instead of creating a new thread for every concurrent task (which is expensive in OS overhead), tasks are submitted to a queue and executed by available pool threads.

Why use it? Reduces thread creation/destruction overhead, improves system responsiveness, and prevents server crashes due to out-of-memory errors from excessive thread creation.

Real-World Analogy

Think of a bank with 5 customer service tellers (Thread Pool). When customers arrive, they take a ticket and wait in the queue. When a teller finishes with a customer, the next person in line steps up. The bank doesn't hire a brand new employee for every single customer walking through the door.

Code Example: ExecutorService

import java.util.concurrent.*;

public class ThreadPoolDemo {
    public static void main(String[] args) {
        ExecutorService pool = Executors.newFixedThreadPool(3);
        for (int i = 1; i <= 5; i++) {
            final int taskId = i;
            pool.execute(() -> System.out.println("Task " + taskId + " executed by " + Thread.currentThread().getName()));
        }
        pool.shutdown();
    }
}

5. Meaning of "Write Anywhere" (WORA)

Definition: "Write Once, Run Anywhere" (WORA) is a core slogan of Java coined by Sun Microsystems. It means that Java code can be written once on any operating system (e.g., Windows) and executed on any other operating system (e.g., Linux, macOS) without needing to recompile or rewrite the code.

How it works:

  1. Java source code (.java) is compiled by the Java compiler into platform-independent intermediate code called Bytecode (.class).
  2. Every operating system has its own implementation of the JVM.
  3. The JVM on that specific OS translates the universal Bytecode into native machine instructions for that hardware.

Real-World Analogy

Think of Java Bytecode as sheet music. A pianist in New York, a flutist in Tokyo, and a guitarist in London can all read the exact same musical notes (Bytecode), and each instrument plays it according to its own capability (JVM translating for Windows/Linux/Mac).

6. String Constant Pool (SCP) & Allocation

Definition: The String Constant Pool (SCP) is a special storage area inside the Java Heap memory dedicated exclusively to storing unique string literals to optimize memory usage.

How JVM allocates and stores strings:

  • Using String Literals (String s = "Hello";): JVM checks the SCP first. If the string already exists, a reference to the existing string is returned. If not, a new string is created in the SCP.
  • Using new Keyword (String s = new String("Hello");): Creates two objects: one in the normal Heap area and another in the SCP (if not already present).
  • The intern() Method: When called on a heap string, it checks if the string is in the SCP. If present, returns the SCP reference; otherwise, adds it to the SCP.

Code Example: SCP & Equality

String s1 = "Java"; // stored in SCP
String s2 = "Java"; // reuses s1 from SCP
String s3 = new String("Java"); // created in Heap

System.out.println(s1 == s2); // true (same memory reference)
System.out.println(s1 == s3); // false (Heap vs SCP)
System.out.println(s1.equals(s3)); // true (same content)

7. How `hashCode()` and `equals()` Work

Definition: `hashCode()` and `equals()` are methods inherited from the root java.lang.Object class, vital for comparing objects and storing them in hash-based data structures like HashMap, HashSet, and Hashtable.

  • Does it generate a new hash code or use the one in Object class? By default, the hashCode() method in the Object class generates an integer hash based on the object's memory address in the heap. However, in classes like String, Integer, or custom POJOs, hashCode() is overridden to calculate a hash value based on the object's actual field values.
  • How Objects are Compared in a HashMap:
    1. When putting or getting a key, hashCode() is called to determine which bucket index to look into.
    2. If multiple objects fall into the same bucket (collision), equals() is called to check if the keys are logically identical.

Code Example: Overriding Contract

class Student {
    int id;
    String name;

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Student s = (Student) obj;
        return id == s.id && Objects.equals(name, s.name);
    }
}

8. Deep Copy vs. Shallow Copy

Definition: These are two ways of duplicating objects in Java.

Shallow Copy

Creates a new object, but copies primitive fields by value and reference fields by address (pointers). Modifying a nested object in the copy affects the original object.

Achieved via: super.clone()

Deep Copy

Creates a completely independent clone. Both primitive fields and all nested reference objects are recursively cloned. Modifying the copy has zero impact on the original.

Achieved via: Copy constructors / Serialization

Real-World Analogy

A Shallow Copy is like making a digital shortcut or hyperlink to a shared Google Doc (if someone edits the target document, both see changes). A Deep Copy is printing a physical photocopy and handing it to another person to edit in isolation.

9. Type Casting Techniques in Industry

Definition: Type casting is the process of converting a variable from one data type to another. In enterprise Java, casting falls into two primary categories:

  • 1. Primitive Type Casting:
    • Widening (Implicit): Small type to large type (int to double). Handled automatically by JVM.
    • Narrowing (Explicit): Large type to small type (double to int). Requires explicit syntax with potential precision loss ((int) 9.87).
  • 2. Reference Type Casting (Polymorphism):
    • Upcasting (Implicit): Subclass reference to Superclass reference (Animal a = new Dog();). Safe and standard in polymorphism.
    • Downcasting (Explicit): Superclass reference back to Subclass reference (Dog d = (Dog) a;). Requires an explicit check using instanceof to avoid ClassCastException.

Code Example: Safe Downcasting

Animal a = new Dog(); // Upcasting
if (a instanceof Dog) {
    Dog d = (Dog) a; // Safe explicit Downcasting
    d.bark();
}

10. Why `String` is Suitable as a HashMap Key

Definition: In Java, String is the most commonly used key in HashMap due to specific architectural design choices:

  • 1. Immutability: Strings are immutable. Once created, their internal state cannot be modified. This is crucial because if a key's value changed after being inserted into a HashMap, its hashCode() would change, making the key unretrievable from its bucket (causing memory leaks or missing data).
  • 2. Cached hashCode(): Since strings are immutable, their hash code is computed once and cached (memoized) during the first hash calculation. Subsequent lookups in HashMaps are extremely fast because recalculating the hash is unnecessary.
  • 3. Thread Safety: Because they are immutable, multiple threads can access a String key concurrently without risk of data corruption or race conditions.

Real-World Analogy

Think of a HashMap key like a permanent postal address code (e.g., "ZIP-10001"). If the postal code kept shifting or changing digits randomly after you mailed a letter, the post office would never be able to locate your package. Because a String is immutable, its address signature remains permanently fixed and reliable.
