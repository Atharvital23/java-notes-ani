2. Prerequisites & Configuration

Before writing Java code, you must establish the dependencies and connection strings.

pom.xml (Dependencies)

Required Condition

You must include Hibernate Core and the MySQL Driver to enable communication.

<!-- Hibernate Core -->
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-core</artifactId>
    <version>6.4.4.Final</version>
</dependency>

<!-- MySQL Connector -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.3.0</version>
</dependency>

hibernate.cfg.xml

Required Condition

Tells Hibernate where the DB is, how to talk to it, and schema generation strategy.

<hibernate-configuration>
  <session-factory>
    <!-- Connection -->
    <property name="hibernate.connection.url">
        jdbc:mysql://localhost:3306/db
    </property>
    <property name="hibernate.connection.username">root</property>
    <property name="hibernate.connection.password">pass</property>
    
    <!-- Dialect -->
    <property name="hibernate.dialect">
        org.hibernate.dialect.MySQLDialect
    </property>

    <!-- Schema condition -->
    <property name="hibernate.hbm2ddl.auto">update</property>
  </session-factory>
</hibernate-configuration>

3. Entity Lifecycle

The crucial conditions dictating *when* your Java object data is actually flushed to the MySQL database.

stateDiagram-v2 [*] --> Transient : new Object() Transient --> Persistent : session.persist() Persistent --> Detached : session.close() Detached --> Persistent : session.merge() Persistent --> Removed : session.remove() Removed --> [*] : Transaction Commit

Transient

Exists in memory. No MySQL equivalent. Condition: Just instantiated using `new`.

Persistent

Managed by Session. Condition: Changes automatically update MySQL on commit.

Detached

Session closed. Condition: Data exists, but won't sync to MySQL unless merged back.

Removed

Condition: Marked for deletion; row will be dropped from MySQL upon commit.

4. Entity Mapping & Annotations

Applying Jakarta Persistence API to transform a plain Java Class into a MySQL Table mapping.

Required Mapping Conditions 
import jakarta.persistence.*;

@Entity // Condition: Marks this class for Hibernate management
@Table(name = "users") // Condition: Maps to specific MySQL table
public class User {

    @Id // Condition: Designates Primary Key
    @GeneratedValue(strategy = GenerationType.IDENTITY) // Condition: Auto-increment (MySQL)
    private Long id;

    @Column(name = "user_name", length = 50, nullable = false, unique = true)
    // Condition: Defines MySQL column constraints
    private String username;
}

In-Depth: Relational Mappings

How Java objects translate to MySQL foreign keys and join tables.

1:1 One-to-One

Example: User & Profile

MySQL Theory: One record in the users table links to exactly one record in the profiles table. This is enforced by placing a Foreign Key (e.g., profile_id) in one of the tables and adding a UNIQUE constraint.

Hibernate Rule: The entity containing the @JoinColumn is the "owning side" (it physically holds the foreign key in the database).

// Owning Side (User table holds the foreign key)
@Entity
public class User {
    @Id private Long id;

    @OneToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "profile_id", referencedColumnName = "id")
    private Profile profile;
}

// Inverse Side (Optional, allows bidirectional navigation)
@Entity
public class Profile {
    @Id private Long id;

    // "mappedBy" tells Hibernate: "Look at the 'profile' property in User class"
    @OneToOne(mappedBy = "profile")
    private User user;
}

1:N One-to-Many

Example: Department & Employees

MySQL Theory: A single Department has many Employees. In a relational database, the Foreign Key (department_id) MUST always reside on the "Many" side (the employees table).

Hibernate Rule: It is best practice to make this bidirectional. The @ManyToOne side is always the owning side. Use mappedBy on the @OneToMany collection side to prevent unwanted extra join tables.

// Owning Side (Many side physically holds the FK)
@Entity
public class Employee {
    @Id private Long id;

    @ManyToOne(fetch = FetchType.LAZY) // Best practice for performance
    @JoinColumn(name = "department_id") // Creates FK column in employee table
    private Department department;
}

// Inverse Side (One side has the Collection)
@Entity
public class Department {
    @Id private Long id;

    @OneToMany(mappedBy = "department", cascade = CascadeType.ALL)
    private List<Employee> employees = new ArrayList<>();
}

N:N Many-to-Many

Example: Students & Courses

MySQL Theory: Students take multiple courses, and courses have multiple students. MySQL cannot link this directly. It explicitly requires a Join Table (e.g., student_course) containing foreign keys linking to both tables.

Hibernate Rule: Use @JoinTable on the owning side to define the intermediate table structure and its columns.

// Owning Side (Defines the Join Table)
@Entity
public class Student {
    @Id private Long id;

    @ManyToMany
    @JoinTable(
        name = "student_course", // Name of the new MySQL join table
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private Set<Course> courses = new HashSet<>();
}

// Inverse Side
@Entity
public class Course {
    @Id private Long id;

    @ManyToMany(mappedBy = "courses")
    private Set<Student> students = new HashSet<>();
}

5. End-to-End Execution (CRUD)

The actual Java code flow required to read and write to MySQL natively.

// 1. Build Factory (ONCE per application)
SessionFactory factory = new Configuration()
    .configure("hibernate.cfg.xml").buildSessionFactory();

// 2. Open Session
Session session = factory.openSession();
Transaction tx = null;

try {
    // 3. Begin TX (Condition: Required for C/U/D)
    tx = session.beginTransaction();
    
    // --- CREATE ---
    User u = new User(); u.setUsername("dev");
    session.persist(u); // MySQL INSERT
    
    // --- READ ---
    User dbUser = session.get(User.class, 1L); // MySQL SELECT
    
    // --- UPDATE ---
    dbUser.setUsername("senior_dev"); // Automatic Dirty Checking
    
    // --- DELETE ---
    session.remove(dbUser); // MySQL DELETE

    // 4. Commit to MySQL
    tx.commit(); 
    
} catch (Exception e) {
    if (tx != null) tx.rollback();
} finally {
    session.close(); // Condition: Prevent memory leaks
}

6. Enterprise Ecosystem: Hibernate, JPA, & Lombok

In modern real-time projects (like Spring Boot microservices), we rarely write the manual code shown in Section 5. Instead, we use industry-standard tools that layer on top of each other.

Hibernate

The Engine (Implementation)

Hibernate is an Object-Relational Mapping (ORM) tool. Its core theory is solving the "Impedance Mismatch"—the fundamental difference between how Java structures data (objects, inheritance, collections) and how MySQL structures data (tables, rows, foreign keys).

  • Writes the JDBC SQL code automatically.
  • Provides First-Level Caching to minimize DB hits.
  • Performs "Dirty Checking" to generate smart UPDATEs.

JPA

The Rulebook (Specification)

JPA (Jakarta Persistence API) is NOT a tool—it is a set of rules and interfaces defined by Java. It contains annotations like @Entity and @Id.

The Relationship: JPA is the interface, Hibernate is the class that implements it. By writing your code using JPA annotations, you theoretically aren't locked into Hibernate; you could switch to another ORM (like EclipseLink) without changing your Java code.

Lombok

The Optimizer (Code Generator)

In enterprise Java, Entities require dozens of lines of Getters, Setters, and Constructors. Project Lombok is a compiler plugin that dynamically generates this boilerplate code at compile time.

  • @Data // Makes Getters/Setters
  • @NoArgsConstructor // Req. by JPA
  • @AllArgsConstructor

7. Real-World Combination (Spring Boot)

How it looks in actual enterprise projects

1. The Clean Entity (JPA + Lombok)

// Lombok removes all boilerplate!
@Data
@NoArgsConstructor
@Entity // JPA handles the mapping
@Table(name = "employees")
public class Employee {
    @Id 
    @GeneratedValue(...)
    private Long id;
    private String name;
}

2. The Repository (Spring Data JPA)

// Spring Data JPA auto-generates Hibernate queries!
public interface EmpRepo 
       extends JpaRepository<Employee, Long> {
    
    // No SQL needed, Spring parses the method name
    List<Employee> findByName(String name);
}

3. The Service Layer (Automatic Transactions)

@Service
@RequiredArgsConstructor // Lombok auto-injects the repo
public class EmpService {
    
    private final EmpRepo repo;

    @Transactional // Spring opens Session & begins TX automatically!
    public void updateName(Long id, String newName) {
        Employee emp = repo.findById(id).orElseThrow();
        emp.setName(newName); 
        // NO session.save() needed! Automatic dirty checking handles the MySQL update.
    }
}

8. Legacy Hibernate to Modern JPA Standard

A complete mapping guide transitioning older, native Hibernate methods to their modern Jakarta Persistence API (JPA) equivalents required in enterprise Spring Boot projects.

Legacy Hibernate Method Modern JPA Alternative Operation Type Primary Behavior & Key Differences
save(entity) persist(entity) Create (Insert) Marks a brand-new entity as persistent. Unlike save(), it does not immediately return an identifier or force an early database INSERT before commit.
update(entity) merge(entity) Update Copies the state of a detached entity onto a managed entity instance. It prevents the common "duplicate object in session" exceptions caused by update().
saveOrUpdate(entity) merge(entity) Save / Update Automatically detects if an entity is new or existing and performs the appropriate save or update action safely.
delete(entity) remove(entity) Delete Schedules a managed entity instance for deletion from the database during the next flush cycle.
get(Class, id) find(Class, id) Read (Eager) Eagerly fetches the entity from the database. Returns null if the record does not exist.
load(Class, id) getReference(Class, id) Read (Lazy) Returns a lightweight runtime proxy object without hitting the database immediately. Throws an exception if accessed and the record doesn't exist.
createQuery(string) createQuery(str, Class) Query (Typed) Creates a type-safe JPQL/HQL query. It eliminates the need for unsafe manual casting when fetching result lists.
createCriteria(Class) getCriteriaBuilder() Query (Dynamic) Legacy Hibernate Criteria is completely removed. You must now use the standard CriteriaBuilder API to build programmatically dynamic queries.
createSQLQuery(string) createNativeQuery(str) Raw SQL Executes a native, database-specific SQL string query instead of HQL/JPQL.
beginTransaction() getTransaction().begin() Transaction Manages local transaction boundaries through the standard EntityTransaction API.
